# 듀얼카메라 동시 촬영으로 카메라·패널 성분 분리 (synthetic 검증)

> 상태: 연구 시뮬레이션. 실기기 검증 전이며, 아래 수치는 모델 가정 안에서의 경향이다.
> 기반: `fix/false-pass-burn-in` @ 517c08e (블록 평균 + Tukey IRLS 저차 radial flat-field).

## 질문

메인+초광각(UW)처럼 위치가 다른 두 후면 카메라로 **한 번에** 촬영하면,
화면 좌표에 고정된 패널 결함과 카메라에 고정된 음영(렌즈 음영 잔차, OLED 시야각 감쇠)을 분리할 수 있는가?
그리고 그게 현재 단일 촬영 flat-field보다 실제로 나은가?

## 핵심 원리

log 휘도로 쓰면 `L_i(x) = p(x) + s_i(x) + o_i + noise`.

- `p`: 패널 성분 (화면 좌표 고정)
- `s_i`: 카메라 i 성분. 렌즈 음영 잔차와 OLED 시야각 감쇠는 둘 다 "카메라에서 화면으로 내린 광축 교점"을 중심으로 한 방사형 함수다.
- 두 카메라는 기선(10~25mm)만큼 떨어져 있으므로 화면 위 중심이 서로 다르다.

두 시점의 차이 `L_1 - L_2 = s_1 - s_2 + 상수`에서는 **패널 성분이 정확히 상쇄된다.** 그래서 이 차이로 `s_1, s_2`를 추정하면 번인이 카메라 성분으로 흡수될 경로가 원리적으로 없다. 남는 미지수는 "두 중심 모두에 대해 방사형인 함수"뿐인데, 중심이 다르면 그건 상수밖에 없다.

단일 촬영은 이 정보가 없다. 그래서 fix 브랜치 주석대로 "화면 전체에 걸친 매끄러운 방사형 패널 열화는 단일 촬영으로 비네팅과 구분할 수 없다."

## 시뮬레이션

`sim_dual_view.py` (numpy만 사용). 설정:

- 6.5" 9:20 폰 화면(68×151mm, 1mm 셀), 거리 150mm, 노이즈 0.3%/셀
- 메인: 대각 반화각 40°, 렌즈 음영 잔차 `1-0.10ρ²-0.04ρ⁴`, principal point 편심 1%
- UW: 반화각 60°, `1-0.16ρ²-0.06ρ⁴`, 화면 해상도가 낮아 PSF σ 1.5셀, 톤커브 선형화 잔차 3%
- OLED 시야각 감쇠 `cos^0.6(시선각)`, 두 카메라 공통
- 광축 교점 추정 오차: 공통 σ 2mm. 카메라 간 상대 오차는 동시 촬영이면 σ 0.5mm(공장 보정된 `LENS_POSE_TRANSLATION` 사용 가정), 수동 이동이면 σ 2mm

비교한 방법:

| 이름 | 설명 |
|---|---|
| main@b1fa38a | 기존 radial bin flat-field (화면 중심 기준) |
| fix-branch | fix 브랜치의 블록 + Tukey IRLS `c0+c1ρ²+c2ρ⁴` (화면 중심 기준) |
| fix-branch+광축 | 같은 모델인데 중심만 추정한 광축 교점으로 |
| dual-joint | 시점 차이로 각 카메라 radial 스플라인(16 knot, 2차 차분 정규화, Huber IRLS)을 추정한 뒤 `p = L_main - s_main` |

`결함 보존%`는 추정 맵을 실제 결함 패턴에 사영한 계수다(100% = 그대로 보존, 0% = 전부 카메라 성분으로 지워짐).

## 결과 (요약, 전체는 `results.md`)

동시 main+UW, 기선 12mm, 정면 촬영:

| 장면 | main@b1fa38a | fix-branch | dual-joint |
|---|---|---|---|
| 번인 없음: 맵 오차 RMS | 0.31% | **0.30%** | 0.48% |
| 상태바+내비바 6% + 얼룩: 보존 | 51% | **101%** | 101% |
| 상태바+내비바 + 세로 그라데이션 4%: 보존 | 68% | 77% | **97%** |
| 중앙 원형 열화 3%: 보존 | 6% | 5% | **104%** |
| 가장자리 방사형 열화 5%: 보존 | 23% | 30% | **102%** |

기울기 5°(정면에서 약간 틀어 촬영)에서는 dual-joint 보존이 87~122%로 흔들리고 노이즈 바닥이 0.73%로 오른다. 수동으로 ±20mm 옮겨 두 장 찍는 경우도 dual-joint는 비슷하게 동작하고(보존 99~104%), 화면이 프레임 중앙에 없으면 단일 촬영 방식은 크게 나빠진다(fix-branch 67%).

## 해석

1. **상태바·내비바 같은 좁은 띠 번인은 fix 브랜치가 이미 해결했다.** 여기서 듀얼은 이득이 없고, 오히려 광축 교점 오차 때문에 노이즈 바닥이 0.30% → 0.48%로 조금 오른다.
2. **듀얼이 진짜 값을 하는 곳은 넓고 매끄러운 패널 성분**(화면 전체 그라데이션, 중앙/가장자리 방사형 열화)이다. 단일 촬영은 원리적으로 70~95%를 지우고, 듀얼은 거의 그대로 보존한다. 오래 쓴 OLED의 넓은 얼룩이나 가장자리 열화가 여기에 해당한다.
3. 그러므로 듀얼은 fix 브랜치 flat-field를 **대체**하는 게 아니라, 단일 촬영이 볼 수 없는 저주파 성분을 **채우는** 역할이 맞다.
4. 성능은 광축 교점을 얼마나 정확히 아는지에 좌우된다. 교점을 데이터로 같이 맞추는 탐색(`refine`)도 시도했는데, 공통 이동 방향이 거의 관측되지 않아 오히려 나빠졌다. 메타데이터로 얻는 게 맞다.

## 모델에 없는 위험 (실기기에서 확인할 것)

- ISP 렌즈 음영 보정(LSC) 잔차가 방사형이 아니면(색 채널별 비대칭, 센서 경사) 방사형 가정이 깨진다. 이 경우 비방사형 저차항 일부는 다시 구분 불가능해진다.
- 카메라별 톤커브/선형화 차이가 3%를 크게 넘으면 패널 성분이 차이 신호에 새어 들어간다.
- UW의 왜곡 보정, 모아레, 서로 다른 AE. 노출·ISO는 두 물리 카메라를 같은 수동 값으로 맞춰야 한다.
- 일부 OEM(특히 삼성)은 서드파티 앱에 물리 카메라 ID를 열어 주지 않는다. 이 경우 동시 촬영이 불가능하므로 "메인으로 좌·우 두 번 찍기"로 폴백한다(시뮬레이션상 성능은 비슷).

## 구현 제안

현재 코드에는 이미 필요한 촬영 경로가 있다. `CaptureController.createTriSession`이 `setPhysicalCameraId`로 3각 동시 세션을 열고, `MeasurementActivity.analyzeCrossRoles`가 화각별 호모그래피·`lumaGrid`를 만든다. 지금은 그 결과를 일치도 confidence로만 쓴다.

1. **`Analyzer.dualViewShading(views)` 추가** (순수 함수, 단위 테스트 가능): 입력은 화각별 *flat-field 전* `lumaGrid`, 화면 좌표의 광축 교점, 유효 셀 마스크(`MultiViewFusion.coverageMask` 재사용). 출력은 화각별 카메라 성분과 잔차 RMS.
2. **광축 교점 계산**: `LENS_INTRINSIC_CALIBRATION`(없으면 센서 중심)의 principal point를 각 화각의 `Homography` 역변환으로 화면 좌표에 투영. 카메라 간 상대 위치는 `LENS_POSE_TRANSLATION`으로 검증.
3. **합성**: 고주파·국소 성분은 fix 브랜치 결과를 그대로 쓰고, 저주파(블록 크기 이상) 성분만 dual-joint 결과로 바꾼다. 자기 검증(차이 신호 잔차가 노이즈 수준인지, 두 결과의 고주파가 일치하는지)에 실패하면 단일 촬영 결과로 폴백하고 로그를 남긴다.
4. **카메라 성분 저장**: 추정한 `s_main`은 같은 기기·같은 거리에서 재사용할 수 있으므로 프로파일로 저장해 이후 단일 촬영에도 쓴다.
5. **평가**: `docs/validation.md` 방식대로 재거치 촬영을 held-out으로 두고, 두 거치에서 추정한 패널 맵이 일치하는지(저주파 성분 포함) 본다. 같은 패널을 180° 회전해 찍었을 때 맵이 같이 회전하는지도 강한 검증이 된다.
